🎯 WHAT IS NETWATCH?
NetWatch is a real-time network traffic monitoring system for LAN/campus environments. It captures network packets, analyzes traffic patterns, identifies bandwidth-heavy devices, and detects anomalies using machine learning.
Core Functionality:

Packet Capture: Uses Scapy to capture network packets on a specific interface
Traffic Analysis: Parses packets to extract bandwidth, protocols, device info
Device Discovery: Identifies active devices via ARP scanning
Bandwidth Monitoring: Calculates real-time upload/download speeds in Mbps
Anomaly Detection: ML model detects unusual traffic patterns
Web Dashboard: Real-time visualization of network activity

Key Technical Details:

Language: Python 3.10+
Framework: Flask (backend), Vanilla JS (frontend)
Database: SQLite with WAL mode
Packet Capture: Scapy with BPF filters
ML: scikit-learn Isolation Forest
Architecture: Multi-threaded (capture, processing, detection, web server)

⚙️ HOW BANDWIDTH MONITORING WORKS
Understanding the Bandwidth Display:
CRITICAL CONCEPT: NetWatch shows actual usage, NOT your internet speed!
Your Internet Speed: 15 Mbps ────┐
                                  │ (Maximum available)
                                  │
Your Actual Usage: 2.5 Mbps ──────┘ (What NetWatch shows)
                                  ▲
                         What you're using right now
Example Scenarios:
ActivityExpected DisplayWhy?Idle (just OS background)10-50 KB/sSmall sync packetsWeb browsing0.5-2 MbpsPage loads, imagesYouTube HD (1080p)3-5 MbpsVideo streaming bitrateYouTube 4K15-25 MbpsHigher bitrateVideo call2-5 MbpsBoth upload & downloadLarge download10-15 MbpsUsing full bandwidthMultiple devicesSum of allAggregate usage
This is CORRECT behavior! If your internet is 15 Mbps but you're only browsing, showing 1 Mbps is accurate.
How Bandwidth is Calculated:
python# Every packet captured:
1. Extract size: 1,500 bytes
2. Add to device total: device_bytes += 1500
3. Add to bandwidth window: last_10_seconds.append((timestamp, 1500))

# Every second:
4. Sum bytes in last 10 seconds: total_bytes = 150,000
5. Calculate rate: bytes_per_second = 150,000 / 10 = 15,000 B/s
6. Convert to Mbps: (15,000 * 8) / 1,000,000 = 0.12 Mbps
7. Display: "0.12 Mbps"
Display Rules:

If >= 1 Mbps: Show as "X.X Mbps" (e.g., "5.3 Mbps")
If 0.01-1 Mbps: Show as "X.XX Mbps" (e.g., "0.75 Mbps")
If < 0.01 Mbps: Show as "XX Kbps" (e.g., "8.5 Kbps")
If < 0.01 Kbps: Show as "XX B/s" (e.g., "50 B/s")

NEVER show raw bytes for bandwidth rate - always convert to Mbps/Kbps!

🔍 HOW DEVICE MONITORING WORKS
Device Discovery Process:
1. ARP Scan (every 2 minutes)
   ↓
2. Finds devices in subnet (10.234.255.0/24)
   ↓
3. Records: IP, MAC, timestamp
   ↓
4. Packet capture sees traffic from these IPs
   ↓
5. Updates: bytes_transferred, last_seen
   ↓
6. Displays: hostname, bandwidth, total data
Device Filtering Rules:
MUST include:

✅ Devices with private IPs in current subnet (10.234.255.x)
✅ Valid MAC addresses (not 00:00:00:00:00:00 or ff:ff:ff:ff:ff:ff)
✅ Seen in last 5 minutes (last_seen check)

MUST exclude:

❌ Broadcast MAC (ff:ff:ff:ff:ff:ff)
❌ Invalid/null MAC (00:00:00:00:00:00)
❌ Wrong subnet (192.168.x.x when on 10.234.255.x)
❌ Multicast IPs (224.x.x.x - 239.x.x.x)
❌ Broadcast IPs (x.x.x.255)

Device Data Accumulation:
How "Total Data" increases:
python# Device A sends packet: 1,500 bytes
device_A.total_bytes += 1500  # Now 1,500

# Device A sends another: 800 bytes  
device_A.total_bytes += 800   # Now 2,300

# Device A receives packet: 1,200 bytes
device_A.total_bytes += 1200  # Now 3,500

# Over time (1 hour of YouTube):
device_A.total_bytes = 1,800,000,000  # 1.8 GB
# Display: "1.8 GB"
This is cumulative since device was first seen!

🧠 HOW ML ANOMALY DETECTION WORKS
Training Process:
1. Collect 20 samples (bandwidth measurements every 30s = 10 minutes)
2. Extract features: bandwidth, protocol counts, connection counts
3. Train Isolation Forest model with contamination=0.05 (5% anomalies expected)
4. Model learns "normal" traffic patterns
Detection Process:
Every 30 seconds:
1. Get current bandwidth
2. Extract features
3. Predict: anomaly = model.predict([features])
4. If anomaly (-1):
   - Create alert: "Unusual bandwidth: X.X Mbps"
   - Severity: warning
5. If normal (1):
   - Continue monitoring
Expected Alerts:
Legitimate anomalies:

Sudden spike from 1 Mbps → 15 Mbps (large download)
New device starts streaming 4K
Background update downloading 10 GB

False positives (can happen):

First time activity (e.g., first video call)
Irregular usage patterns
Solution: Model retrains over time with more data
